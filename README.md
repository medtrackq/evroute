# วางแผนชาร์จ EV ทั่วไทย

เว็บวางแผนเดินทางด้วยรถยนต์ไฟฟ้าในประเทศไทย เลือกรุ่นรถ ใส่แบตที่เหลือ ต้นทางและปลายทาง แล้วระบบจะบอกว่าควรแวะชาร์จที่สถานีไหนบ้างตลอดทาง เพื่อไม่ให้แบตหมดกลางทาง

## ฟีเจอร์

- **อยากแวะ (ไม่บังคับ)**: เลือก 🍜 กินข้าว · ☕ กาแฟ · 🚻 ห้องน้ำ · 🛍 ห้าง/ร้านค้า แล้วระบบเลือกจุดชาร์จที่มีให้ ถ้าไม่ต้องอ้อมไกล (หักคะแนนจุดที่ไม่มี 15 นาทีต่ออย่างใน `plan.js`) "กินข้าว" นับเฉพาะจุดที่ถึงช่วงมื้ออาหาร (06:30–09:00, 11:00–13:30, 17:30–20:30) ตามเวลาออกเดินทาง ผลลัพธ์บอกว่าแวะได้อะไร และใช้เวลาเพิ่มกี่นาทีเทียบกับแผนที่ไม่เลือก ทุกจุดแวะแสดงสิ่งที่อยู่ในระยะเดิน ~250 ม. และลิงก์ "ร้านอาหารแถวนี้ (Wongnai)" ข้อมูลร้านมาจาก OpenStreetMap (`lib/amenities.mjs`: server ถาม Overpass รอบสถานีของเรา สัปดาห์ละครั้ง ดูได้ที่ `/api/places` และเก็บเป็น `data/places-th.json` ได้เพื่อไม่ต้องถามใหม่ทุกครั้งที่ server เริ่ม) ถ้าแผนที่ไม่มีข้อมูล จะเดาจากชื่อสถานี/เครือข่าย เช่น ปั๊ม PTT มี Café Amazon, 7-Eleven, ห้องน้ำ โดยแสดงว่า "(น่าจะมี)"
- **3 ภาษา: ไทย · English · 中文** (ปุ่มเลือกภาษาที่หัวเว็บ หรือ `?lang=en` / `?lang=zh`) ครั้งแรกใช้ภาษาไทย ยกเว้นเบราว์เซอร์ไม่มีภาษาไทยเลย (นักท่องเที่ยว) เว็บเขียนเป็นภาษาไทย แล้ว `assets/js/i18n.js` แปลข้อความไทยที่แสดงบนหน้าจอจากพจนานุกรม `assets/i18n/en.js`, `zh.js` (`phrases` = ประโยคทั้งประโยค ตัวเลขเขียนเป็น `#`, `runs` = คำ/วลีไทยแต่ละช่วง) ชื่อสถานี ที่อยู่ และชื่อสถานที่คงเป็นภาษาไทย วันที่และตัวเลขเปลี่ยนตามภาษา **เมื่อเพิ่มข้อความไทยใหม่ในโค้ด ต้องเพิ่มคำแปลในสองไฟล์นี้ด้วย** ไม่อย่างนั้นจะแสดงเป็นภาษาไทย
- **หน้าแรกแบบวิดเจ็ต**: ส่วนหัวสีเข้มทักทายตามเวลา (เช้า/เที่ยง/บ่าย/เย็น/ค่ำ) พร้อมชื่อเล่น (ไม่บังคับ) รูปรถ และข้อความสั้น ๆ ที่เปลี่ยนไปตามช่วงเวลาและวัน ตามด้วยการ์ด: แบตเตอรี่, ทริปถัดไป, อากาศที่ปลายทางในวันเดินทาง (Open-Meteo ผ่าน `/api/weather`), สถานีชาร์จใกล้ฉัน (ขออนุญาตตำแหน่งเมื่อกด พร้อมแผนที่ย่อ), ทางลัด, ค่าไฟตอนนี้ (On/Off-Peak ตามเวลาไทย), เคล็ดลับ, ทริปที่บันทึกไว้ บนมือถือมีแถบเมนูลอยด้านล่าง (หน้าแรก · วางแผน · แผนที่ · บัญชี)
- **การ์ด "รถของฉัน เดือนนี้"** (เข้าสู่ระบบแล้ว): ค่าชาร์จเดือนนี้จากบันทึกการชาร์จของตัวเอง, ประหยัดกว่ารถน้ำมันเท่าไร (เทียบตาม `petrol` ใน `data/prices.json` แก้ตามราคาน้ำมันได้) และอัตรากินไฟจริงเทียบค่าโรงงาน พร้อมปุ่มใช้ค่านี้วางแผน
- **ติดตั้งเป็นแอปบนหน้าจอโฮม** (`manifest.webmanifest`, `sw.js`, ไอคอนใน `assets/icons/`): Android/Chrome มีปุ่ม "ติดตั้ง" บน iPhone มีคำแนะนำให้แตะแชร์ → เพิ่มไปยังหน้าจอโฮม เปิดแบบเต็มจอ และเปิดได้แม้ไม่มีเน็ต (หน้าเว็บล่าสุดที่เคยเปิด)
- **3 มุมมอง**: หน้าแรก → ฟอร์มวางแผน → ผลลัพธ์ หลังวางแผน ฟอร์มยุบเหลือแถบเดียว (เส้นทาง · รถ · แบต · เวลาออก · แก้ไข) ผลลัพธ์ขึ้นก่อน แต่ละจุดชาร์จแสดงแค่แบต/เวลา/ค่าไฟ กับปุ่มเปิดแอปและนำทาง รายละเอียดอื่นพับไว้ บนมือถือมีแถบปุ่ม "เปิดใน Google Maps" และ "บันทึก" ลอยด้านล่าง

- **เลือกยี่ห้อ/รุ่นรถ** (BYD, MG, GWM ORA, Tesla, NETA, AION, Deepal, ZEEKR, XPENG, Volvo, Hyundai, Kia, Toyota, BMW, Mercedes-Benz, Nissan, VinFast, Wuling และ "กำหนดเอง") ระบบมีค่าความจุแบต อัตรากินไฟ กำลังชาร์จ DC สูงสุด และชนิดหัวของแต่ละรุ่น ผู้ใช้ปรับเองได้ในเมนู "ปรับค่ารถ" (รวมถึง % ที่เผื่อไว้สำหรับแอร์ สัมภาระ ฝน)
- **แบตตอนออกเดินทาง** ใส่เป็น % หรือระยะวิ่งที่เหลือ (กม.), ตั้ง **"แวะชาร์จเมื่อแบตเหลือ"** (10–40%) และ **"ชาร์จถึง"** (60–100%)
- **ต้นทาง/ปลายทาง** พิมพ์ชื่อสถานที่ ใช้ตำแหน่งของฉัน หรือแตะบนแผนที่
- **หลายจุดหมาย และไป-กลับ**: ปุ่ม "เพิ่มจุดหมาย" (สูงสุด 5 จุด: B, C, D …) และสวิตช์ "ไป-กลับ" ให้กลับมาที่ต้นทาง ระบบคิดแบตต่อเนื่องทั้งทริป (ไม่ได้ชาร์จที่จุดหมาย) และหาจุดชาร์จได้ทั้งขาไปและขากลับ
- **แผนการชาร์จหลายจุด** ตามลำดับ กม. บนเส้นทาง: ชื่อสถานี ผู้ให้บริการ หัวชาร์จ/kW แบตตอนถึง → ชาร์จถึงกี่ % เวลาชาร์จโดยประมาณ และ kWh ที่เติม
- **ปรับแผนเองได้**: "เปลี่ยนสถานี" (เลือกสถานีอื่นในช่วงเดียวกัน), "ไม่แวะที่นี่" หรือแตะสถานีบนแผนที่แล้วกด "แวะชาร์จที่นี่" ระบบคำนวณช่วงที่เหลือให้ใหม่
- **เปิดเส้นทางทั้งหมดใน Google Maps** โดยใส่จุดชาร์จและจุดหมายของผู้ใช้เป็นจุดแวะ (waypoints หรือ "Add destination") ตามลำดับเส้นทางให้อัตโนมัติ ผู้ใช้ไม่ต้องกรอกเอง และลิงก์นำทางทีละช่วง (เพราะแอป Google Maps บนมือถือบางเครื่องรับจุดแวะได้ไม่เกิน 3 จุด)
- **ปุ่ม "เปิดแอป …"** ของผู้ให้บริการแต่ละสถานี (Android → เปิดแอป/Play Store, iPhone → App Store, คอมพิวเตอร์ → เว็บไซต์) ลิงก์ตรงไปหน้าสถานีในแอปยังทำไม่ได้ เพราะผู้ให้บริการไม่ได้เปิดลิงก์แบบนั้น จึง**คัดลอกคำค้นให้ก่อนเปิดแอป**: ชื่ออำเภอของสถานี (อำเภอเมือง → ตำบล; ถ้าที่อยู่ไม่มีอำเภอ หาจากพิกัดผ่าน Photon) ซึ่งเจอสถานีในแอปได้ในไม่กี่รายการ ข้อความบอกสั้น ๆ ว่าแตะช่องค้นหา → วาง → เลือกสถานีที่ตำบลไหน
- **ผู้ใช้เพิ่มสถานีที่ยังไม่มีได้เอง** (ปุ่ม "เพิ่มสถานีชาร์จ" ใต้แผนที่ หรือในข้อความ "ไปไม่ถึง") ปักหมุดบนแผนที่ / ใช้ตำแหน่งปัจจุบัน / วางลิงก์ Google Maps แล้วใส่ผู้ให้บริการ ชื่อ หัวชาร์จ (ชนิด, kW, จำนวน) เวลาเปิด สถานีใช้วางแผนได้ทันทีและทุกคนเห็น พร้อมป้าย "ผู้ใช้เพิ่ม"
- **ค่าไฟโดยประมาณเป็นบาท** ต่อจุดและรวมทั้งทริป ตามราคาที่แต่ละเครือข่ายประกาศ (`data/prices.json`) เลือกราคา On-Peak/Off-Peak ตามเวลาที่คาดว่าจะไปถึงแต่ละจุด (ออกเดินทางตอนนี้) และคิดพลังงานที่หัวชาร์จจ่ายมากกว่าที่เข้าแบต ~10% เครือข่ายที่ไม่มีราคาใช้ราคาเฉลี่ย
- **วันเวลาออกเดินทาง** ว่างไว้ = ออกตอนนี้ หรือเลือกล่วงหน้า ค่าไฟ On/Off-Peak และเวลาถึงคิดตามวันนั้น (อยู่ในลิงก์แผนด้วย)
- **บันทึกแผน** (เก็บในเบราว์เซอร์ ไม่ต้อง login) สูงสุด 20 แผน พร้อมวันเดินทาง: ทริปที่ใกล้ถึงขึ้นก่อน ทริปที่ผ่านไปแล้วกดเปิดเพื่อใช้อีกครั้ง (ระบบให้เลือกวันใหม่) และเมื่อบันทึกด้วยวันใหม่ จะแทนที่ของเก่า
- **สถานีโปรด ★** กดดาวจากรายการหรือ popup บนแผนที่ ระบบเลือกสถานีโปรดก่อนเมื่อเสียเวลาเพิ่มไม่มาก
- **บันทึกการชาร์จจริง** ปุ่มในแต่ละจุดชาร์จ: ชาร์จได้/ไม่ได้ (ถ้าไม่ได้ เลือกสาเหตุ เช่น ตู้เสีย คิวยาว ไม่มีหัวที่ใช้ได้) หัวที่ใช้ แบตก่อน/หลัง kWh ที่ได้ ค่าไฟที่จ่าย เวลา กำลังสูงสุดที่เห็น เลขไมล์ และหมายเหตุ (ต้องเปิดสถิติการใช้งาน) บันทึก 90 วันล่าสุดถูกนำมาแสดงที่สถานี: "✓ ผู้ใช้ชาร์จได้จริง N ครั้ง" และหัวที่มีคนชาร์จได้จะถือว่ายืนยันแล้ว (ใช้กำลังสูงสุดที่เห็น) ส่วนสถานีที่รายงานล่าสุด (ภายใน 14 วัน) บอกว่าชาร์จไม่ได้ จะแสดงคำเตือน และตัววางแผนหลีกเลี่ยง (คิดเหมือนเสียเวลาเพิ่ม 60 นาที) ยกเว้นไม่มีทางเลือกอื่นหรือผู้ใช้เลือกสถานีนั้นเอง
- **บัญชี (ไม่บังคับ)**: ใช้ทุกอย่างได้โดยไม่ต้องสมัคร ถ้าต้องการเก็บทริปไว้ทุกเครื่อง ใส่อีเมลแล้วรับรหัสทางอีเมล (ไม่มีรหัสผ่าน) ได้ทริปข้ามเครื่อง ประวัติการชาร์จ ค่าชาร์จรายเดือน และอัตรากินไฟจริงของรถจากเลขไมล์ (กด "ใช้ค่านี้วางแผน" ได้) ระบบชวนสมัครเฉพาะตอนที่เพิ่งทำสิ่งที่อยากเก็บ (บันทึกแผน ตั้งวันเดินทางล่วงหน้า ส่งบันทึกการชาร์จ เปิดในเครื่องใหม่) ครั้งเดียวต่อเรื่อง ลบบัญชีเองได้ทันที ดู `privacy.html`
- **สถิติการใช้งานแบบไม่ระบุตัวตน** (ไม่บังคับ ดูหัวข้อด้านล่าง) ผู้ใช้กด "ไม่ร่วมส่งสถิติ" ท้ายหน้าได้
- ลิงก์แผนแชร์ได้ (ทุกค่าอยู่ใน URL), รองรับมือถือ, ภาษาไทย, สลับโหมดสว่าง/มืด

## วิธีคำนวณ

1. ขอเส้นทาง A → B จาก Valhalla พร้อมเวลาและระยะของแต่ละช่วงถนน
2. คิดพลังงานต่อ กม. จากค่ากินไฟของรถ × ตัวคูณตามความเร็วของช่วงนั้น (50 กม./ชม. ≈ 0.9×, 80 ≈ 1.0×, 100 ≈ 1.12×, 120 ≈ 1.3×) + % ที่เผื่อไว้
3. เลือกสถานีชาร์จ DC ที่ใช้กับหัวของรถได้ ห่างจากเส้นทางไม่เกิน 5 กม. (คิดระยะอ้อมเข้า-ออก)
4. หาชุดจุดแวะที่ใช้ **เวลารวมน้อยที่สุด** (ขับ + อ้อม + ชาร์จ + 5 นาทีต่อจุดสำหรับจอด/เสียบสาย) ด้วย dynamic programming โดยแบตไม่ต่ำกว่าค่าที่ตั้ง และแต่ละจุดชาร์จเท่าที่ช่วงถัดไปต้องใช้ (+2%) ไม่เกินค่า "ชาร์จถึง"
5. เวลาชาร์จใช้กำลัง = min(กำลังสถานี, กำลังรถ) ลดลงเมื่อแบตเกิน 50% และลดมากหลัง 80%
6. ขอเส้นทางจริงผ่านจุดแวะทั้งหมดอีกครั้ง แล้วคำนวณแบตแต่ละช่วงใหม่จากเส้นทางนั้น

ตัวเลขทั้งหมดเป็นค่าประมาณ ระยะวิ่งจริงขึ้นกับการขับ อากาศ ทางขึ้นเขา และสภาพแบต

### Google Places: เติมสถานีที่ขาด (ไม่บังคับ)

ข้อมูลฟรีขาดสถานีหลายเครือข่าย (EA, PTT PluZ, EleXA ฯลฯ) เมื่อตั้ง key ของ Google ไว้ ระบบจะ**ขอสถานีจาก Google เฉพาะช่วงเส้นทางที่ข้อมูลเราไม่พอ**:
- แผนที่ "ไปไม่ถึง" → ค้นรอบ ๆ ช่วงที่แบตจะหมด แล้ววางแผนใหม่ ทำซ้ำได้ถึง 5 รอบ ไม่เกิน 12 จุดค้นหาต่อการวางแผน 1 ครั้ง
- แผนที่ไปได้อยู่แล้ว → ค้นเฉพาะช่วงที่สถานีห่างกันมาก ไม่เกิน 3 จุด
- จุดที่ค้นแล้วจะไม่ค้นซ้ำในการเปิดหน้าเว็บครั้งเดียวกัน · ค้นวงกลมรัศมี 25 กม. ได้สูงสุด 20 สถานีต่อครั้ง
- **กวาดหา PTT EV Station PluZ ทั่วประเทศ เดือนละครั้ง** (`lib/sweep.mjs`): server แบ่งประเทศไทยเป็นช่องราว 45 กม. (393 ช่อง) ถาม Google Text Search ช่องละครั้ง 3 รอบ (1. "PTT EV Station PluZ" เฉพาะสถานีชาร์จ 2. "PluZ" ทุกประเภท เก็บเฉพาะชื่อที่บอกว่าชาร์จได้ 3. "PTT Station พีทีที สเตชั่น" เฉพาะสถานีชาร์จ เพราะหลายสาขาใช้ชื่อปั๊มเจ้าของที่) ช่องที่ได้คำตอบเต็ม 20 แห่ง (เมืองใหญ่) แบ่งเป็น 4 แล้วถามใหม่ ขอเฉพาะ id ชื่อ และตำแหน่ง = ราคา "Pro" (ฟรี 5,000 ครั้ง/เดือน) เก็บเฉพาะ place id ตำแหน่ง และเครือข่าย ไม่เกิน 30 วันตามเงื่อนไข Google (ตาราง `sweeps`, `swept_places`) แล้วกวาดใหม่ทุก 27 วัน หยุดกลางทาง (เช่น server รีสตาร์ท หรือ Google ตอบ error) จะทำต่อจากเดิมในรอบตรวจถัดไป (ทุก 6 ชม.) เพดาน `SWEEP_MAX_CALLS` (ค่าเริ่มต้น 3,000 ครั้งต่อรอบ) หน้าเว็บโหลด `/api/google/swept` เฉพาะตอนแสดงแผนที่ Google ดูสถานะและกด "เริ่มกวาดตอนนี้" ได้ที่หลังบ้าน (สถานะระบบ) **ต้องตั้งโควต้า Places API ใน Google Cloud ให้พอ** (เช่น 1,500 ครั้ง/วัน) ไม่อย่างนั้นการกวาดจะติดโควต้ารายวัน
- **ค้นหา PTT EV Station PluZ ตามจุดแวะ (ช่วงทดสอบ)**: PluZ มีกว่า 1,350 แห่ง แต่ไม่เปิดเผยรายชื่อ ข้อมูลฟรีจึงมีแค่ราว 40 แห่ง เมื่อวางแผนเสร็จ แอปถาม Google (Text Search ด้วยชื่อ) รอบจุดแวะชาร์จแต่ละจุด รัศมี 20 กม. สูงสุด 4 จุดต่อแผน แล้ววางแผนใหม่ ใช้โควต้าวันละ `GOOGLE_DAILY_LIMIT` เดียวกัน (1 จุด = 1 ครั้ง) ถ้าได้รายชื่อจาก OR โดยตรงแล้ว ตัดส่วนนี้ออกได้ (`findBrand` ใน `app.js`)
- server จำกัดไม่เกิน `GOOGLE_DAILY_LIMIT` ครั้งต่อวัน (ค่าเริ่มต้น 30 ≈ 900/เดือน อยู่ในโควตาฟรี 1,000 ครั้ง/เดือน) และ 20 ครั้ง/ชั่วโมงต่อ IP เมื่อครบ แอปจะใช้ข้อมูลฟรีต่อตามปกติ

ราคา (ณ ต.ค. 2026): ฟิลด์ข้อมูลหัวชาร์จ `evChargeOptions` อยู่ใน SKU "Nearby Search Enterprise + Atmosphere" ฟรี 1,000 ครั้ง/เดือน หลังจากนั้น $40 ต่อ 1,000 ครั้ง · แผนที่ Google Maps ฟรี 10,000 ครั้ง/เดือน

เงื่อนไขของ Google ที่ระบบทำตามแล้ว: ข้อมูลจาก Places ต้องแสดงบนแผนที่ Google (เมื่อเปิดใช้ หน้าเว็บจะเปลี่ยนเป็น Google Maps เอง) · ห้ามเก็บข้อมูลไว้ใช้ซ้ำ (เก็บแค่ในหน้าเว็บที่เปิดอยู่) · แสดงเครดิตและลิงก์ "ข้อมูลจาก Google Maps" ทุกสถานีที่มาจาก Google

ตั้งค่า:
1. [Google Cloud Console](https://console.cloud.google.com) → สร้างโปรเจกต์ → ผูก Billing
2. เปิด **Places API (New)** และ **Maps JavaScript API**
3. สร้าง key 2 ตัว: (ก) สำหรับ server จำกัด API = Places API (New) (ข) สำหรับแผนที่ จำกัด Website = โดเมนเว็บบน Render, API = Maps JavaScript API
4. **ตั้งเพดานจริง**: APIs & Services → Places API (New) → Quotas → จำกัด requests per day (เช่น 30) งบประมาณ (Budget) แค่แจ้งเตือน ไม่ได้หยุดการเรียก
5. (แนะนำ) สร้าง Map ID ที่ Google Maps Platform → Map management แล้วใส่ใน `GOOGLE_MAP_ID` (ไม่ใส่จะใช้ `DEMO_MAP_ID` ซึ่งใช้ทดสอบได้)
6. Render → Environment: `GOOGLE_PLACES_KEY` = key (ก), `GOOGLE_MAPS_KEY` = key (ข), (ไม่บังคับ) `GOOGLE_MAP_ID`, `GOOGLE_DAILY_LIMIT`

ถ้าไม่ตั้ง หรือโหลดแผนที่ Google ไม่ได้ เว็บใช้แผนที่ OpenStreetMap และข้อมูลฟรีตามเดิม

### สถานีที่ผู้ใช้เพิ่ม

Render แบบฟรีจะล้างไฟล์ทุกครั้งที่ deploy หรือ restart จึงเก็บรายการไว้ใน **GitHub**: ไฟล์ `user-stations.json` ใน branch `user-data` ของ repo นี้ (server สร้าง branch ให้เองครั้งแรก) ฟรี ไม่หาย มีประวัติทุกครั้งที่มีคนเพิ่ม และการเขียนลง branch นี้ไม่ทำให้เว็บ deploy ใหม่

ตั้งค่าใน Render → Environment:

| ตัวแปร | ค่า |
| --- | --- |
| `GITHUB_TOKEN` | Fine-grained personal access token: Repository access = เฉพาะ `medtrackq/evroute`, Permissions → Contents = **Read and write** |
| `GITHUB_REPO` | `medtrackq/evroute` |
| `GITHUB_DATA_BRANCH` | (ไม่บังคับ) ค่าเริ่มต้น `user-data` |

ถ้าไม่ตั้ง จะเก็บใน `data/user-stations.json` บนเครื่อง (ใช้ตอนรันในเครื่อง; บน Render จะหายเมื่อ restart)

- **ตรวจ/ลบ**: เปิด `user-stations.json` ใน branch `user-data` บน GitHub ดูประวัติ commit ได้ว่าใครเพิ่มอะไรเมื่อไร ถ้าข้อมูลผิดหรือสแปม แก้ไฟล์ใส่ `"hidden": true` ที่สถานีนั้น (หรือลบออก) server อ่านไฟล์ใหม่ทุก 10 นาที
- **ย้ายเข้ารายการหลัก**: สถานีที่ตรวจแล้วคัดลอกไปใส่ `data/stations.json` ได้เลย (รูปแบบเดียวกัน)
- **กันสแปม**: ตรวจข้อมูลทุกช่อง รับเฉพาะพิกัดในประเทศไทย และจำกัด 10 สถานี/ชั่วโมงต่อ IP (ไม่ได้เก็บ IP หรือข้อมูลส่วนตัวของผู้ใช้)

### สถิติการใช้งาน (Supabase, ไม่บังคับ)

เก็บข้อมูลแบบไม่ระบุตัวตนลงฐานข้อมูล Postgres ของ [Supabase](https://supabase.com) (แผนฟรี 500 MB) เพื่อดูว่าคนใช้รถรุ่นไหน กินไฟจริงเท่าไร ชาร์จที่ไหน และกดเปิดแอปผู้ให้บริการไหนบ้าง

| ตาราง | หนึ่งแถวคือ | ข้อมูล |
| --- | --- | --- |
| `plans` | การวางแผน 1 ครั้ง | รถ (ยี่ห้อ รุ่น แบต อัตรากินไฟที่ตั้ง เทียบค่าโรงงาน) % ออกเดินทาง/แวะชาร์จ/ชาร์จถึง ต้นทาง-ปลายทาง (ปัดเหลือ ~10 กม.) ระยะ เวลา ค่าไฟ และสถานีที่เลือกทุกจุด |
| `events` | การกดปุ่ม 1 ครั้ง | เปิดแอปผู้ให้บริการ (`app`), นำทาง (`nav`, `nav_leg`, `nav_stop`), ไม่แวะ (`skip`), เปลี่ยนสถานี (`swap`), เลือกสถานีจากแผนที่ (`pin`), สถานีโปรด (`fav`), บันทึก/แชร์แผน (`save`, `share`) |
| `charges` | บันทึกการชาร์จจริง 1 ครั้ง | สถานี ชาร์จได้หรือไม่และสาเหตุ แบตก่อน/หลัง kWh บาท นาที kW สูงสุด เลขไมล์ หมายเหตุ |

ทุกแถวผูกกันด้วยรหัสสุ่มของแต่ละแผน (`plan_id`) และรหัสสุ่มของรถ (`car_uid` เช่น `c-7f3k9x2m`: เบราว์เซอร์สร้างให้รุ่นละหนึ่งรหัส จึงรู้ว่าทริปและบันทึกการชาร์จไหนมาจากรถคันเดียวกัน ผู้ใช้กด "เริ่มรหัสใหม่" ท้ายหน้าเพื่อตัดความเชื่อมโยงกับข้อมูลเดิมได้) **ไม่เก็บ IP ชื่อ เบอร์โทร ทะเบียนรถ หรือตำแหน่งละเอียดของผู้ใช้** server สร้างแต่ละแถวใหม่จากรายการช่องที่อนุญาตเท่านั้น (`lib/stats.mjs`) ข้อมูลอื่นที่ส่งมาจะถูกทิ้ง ผู้ใช้กด "ไม่ร่วมส่งสถิติ" ท้ายหน้าได้ ส่วนบันทึกการชาร์จจริงส่งเมื่อผู้ใช้กดส่งเองเท่านั้น

ตั้งค่า:
1. สมัคร Supabase → **New project** (Region: Singapore) ตั้งรหัสผ่านฐานข้อมูลแล้วเก็บไว้
2. **SQL Editor** → New query → วางเนื้อหา `db/schema.sql` → **Run** (สร้าง 3 ตาราง และ view สรุป `car_usage`, `app_opens`, `station_reports`, `car_consumption` = อัตรากินไฟจริงต่อรุ่นจากเลขไมล์และ % แบตในบันทึกการชาร์จ, `car_returns` = รถกลับมาใช้ซ้ำแค่ไหน) ไฟล์นี้รันซ้ำได้ เมื่ออัปเดตโค้ดให้รันใหม่เพื่อเพิ่มคอลัมน์/view ที่ขาด
3. **Project Settings → API**: คัดลอก **Project URL** และ **secret key** (`service_role`; ไม่ใช่ `anon`/publishable)
4. Render → Environment: `SUPABASE_URL` = Project URL, `SUPABASE_KEY` = secret key

secret key อยู่บน server เท่านั้น ตารางเปิด row level security โดยไม่มี policy จึงอ่าน/เขียนด้วย key สาธารณะไม่ได้ ดูข้อมูลได้ใน **Table Editor** หรือเขียน SQL เอง ถ้าไม่ตั้งสองตัวแปรนี้ หน้าเว็บจะไม่ส่งอะไรเลย และไม่แสดงปุ่มบันทึกการชาร์จ

### บัญชีผู้ใช้ (Supabase Auth, ไม่บังคับ)

เปิดเองเมื่อตั้ง `SUPABASE_URL` + `SUPABASE_KEY` แล้ว (ใช้โปรเจกต์เดียวกับสถิติ) หน้าเว็บคุยกับ server ของเราเท่านั้น server เรียก Supabase Auth ด้วย secret key ตาราง `trips` เก็บทริปของแต่ละคน และ `charges.user_id` เชื่อมบันทึกการชาร์จกับเจ้าของ ลบผู้ใช้แล้วทริปถูกลบตาม บันทึกการชาร์จเหลือแบบไม่ระบุตัวตน view `signup_funnel` นับการชวนสมัครแต่ละจุด (แสดง/กด/สมัครสำเร็จ) และคนที่กดสนใจสมาชิกรุ่นแรก

ตั้งค่าใน Supabase:
1. **SQL Editor**: รัน `db/schema.sql` อีกครั้ง
2. **Authentication → URL Configuration → Site URL** = `https://evroute.onrender.com` (ค่าเริ่มต้นคือ localhost) เพราะลิงก์ในอีเมลพากลับมาที่นี่ หน้าเว็บรับทั้งการกดลิงก์ในอีเมล (อีเมลแบบเริ่มต้นของ Supabase) และการพิมพ์รหัส
   - **Authentication → Emails → Templates**: Supabase ให้แก้แม่แบบได้หลังตั้ง SMTP เองแล้ว (ข้อ 3) จากนั้นแก้ทั้ง **Magic Link** และ **Confirm signup** ให้มีรหัส `{{ .Token }}` (ตัวอย่างด้านล่าง) ผู้ใช้จะพิมพ์รหัสได้ ซึ่งดีกว่าลิงก์บนมือถือ (ลิงก์มักเปิดในเบราว์เซอร์อื่น)
3. **Authentication → Emails → SMTP Settings**: ใส่ SMTP ของผู้ให้บริการส่งอีเมล เช่น Resend (ฟรี 3,000 ฉบับ/เดือน) ระบบส่งอีเมลในตัวของ Supabase ส่งได้เฉพาะอีเมลของสมาชิกทีมโปรเจกต์ และจำนวนน้อยมาก ใช้ทดสอบเท่านั้น
4. (ไม่บังคับ) Render → `CONTACT_EMAIL` = อีเมลติดต่อเรื่องข้อมูลส่วนบุคคล แสดงในหน้านโยบาย

ตัวอย่างอีเมล (Subject: `รหัสเข้าสู่ระบบ EVROUTE: {{ .Token }}`):

```html
<h2>รหัสเข้าสู่ระบบ EVROUTE</h2>
<p>ใส่รหัสนี้ในหน้าเว็บ:</p>
<p style="font-size:28px;font-weight:700;letter-spacing:4px">{{ .Token }}</p>
<p>รหัสใช้ได้ครั้งเดียวและหมดอายุใน 1 ชั่วโมง ถ้าคุณไม่ได้ขอรหัสนี้ ไม่ต้องทำอะไร</p>
```

### หลังบ้าน (admin.html)

หน้า `/admin.html` สำหรับเจ้าของแอป อัปเดตทุก 1 นาที:

- **จำนวนคนใช้**: วันนี้ / 7 วัน / 30 วัน และกลับมาใช้ซ้ำ นับจากเหตุการณ์ `open` วันละครั้งต่อเบราว์เซอร์ (รหัสสุ่ม `dev`) กราฟรายวัน 30 วัน, จำนวนแผน, บัญชีผู้ใช้, สมัครใหม่
- **ข้อผิดพลาดของโปรแกรม**: จากหน้าเว็บ (`window.onerror`, วางแผนไม่สำเร็จ) และจากเซิร์ฟเวอร์ (Overpass, Google, Supabase, เส้นทาง ฯลฯ) รวมข้อความเดียวกันเป็นแถวเดียว พร้อมจำนวนครั้ง จำนวนคน และเบราว์เซอร์
- **ข้อความจากผู้ใช้**: จากปุ่ม "ติดต่อเรา / แจ้งปัญหา" (ท้ายหน้าแอป และในเมนูบัญชี) กด "เสร็จแล้ว" เมื่อจัดการแล้ว อีเมลกดตอบได้เลย
- **คนมาจากช่องทางไหน**: จากลิงก์ `?ref=tiktok` (หรือ `utm_source`) และตรวจเองจากแอป/เว็บที่ส่งมา (Facebook, Instagram, TikTok, LINE, Google, YouTube, Pantip) เป็นเหตุการณ์ `arrive` พร้อม `ref` มีลิงก์สำเร็จรูปให้คัดลอกในหน้าหลังบ้าน พารามิเตอร์เหล่านี้ถูกลบออกจากที่อยู่ทันที ลิงก์ที่แชร์ต่อจึงไม่พาไปด้วย
- สถานีที่ผู้ใช้แจ้งว่าชาร์จไม่ได้, ภาษาที่ใช้, รุ่นรถยอดนิยม, การเปิดแอปผู้ให้บริการ, ปุ่มที่กด, สถานะระบบ (โควต้า Google, แหล่งข้อมูลสถานี)

ตั้งค่า:
1. Supabase → SQL Editor: รัน `db/schema.sql` อีกครั้ง (เพิ่มตาราง `errors`, `feedback` และคอลัมน์ `dev`, `lang`)
2. Render → Environment: `ADMIN_EMAILS` = อีเมลผู้ดูแล (หลายคนคั่นด้วย `,`) และ (แนะนำ) `CONTACT_EMAIL` = อีเมลที่แสดงให้ผู้ใช้ติดต่อ
3. เปิดแอป → เข้าสู่ระบบด้วยอีเมลผู้ดูแล → ไปที่ `https://<โดเมน>/admin.html`

### ภาพตัวอย่างเวลาแชร์ลิงก์

`index.html` มีแท็ก `og:` (Facebook, LINE, X) server (`lib/share.mjs`) ใส่ URL เต็ม ภาพตามภาษาของลิงก์ (`assets/og.png`, `og-en.png`, `og-zh.png` ขนาด 1200×630) และชื่อทริปเมื่อแชร์แผน เช่น "กรุงเทพฯ → เชียงใหม่ · แผนชาร์จ EV" ถ้า Facebook ยังแสดงภาพเก่า ใช้ [Sharing Debugger](https://developers.facebook.com/tools/debug/) กด Scrape Again

### รูปรถ

รูปแต่ละรุ่นมาจาก [Wikimedia Commons](https://commons.wikimedia.org) (CC BY-SA / CC0) ใน `data/car-images.json` พร้อมชื่อช่างภาพและใบอนุญาต ซึ่งแสดงใต้รูปในหน้าเว็บตามเงื่อนไขของใบอนุญาต (ห้ามเอาเครดิตออก) รูปโหลดจากเซิร์ฟเวอร์ของ Wikimedia โดยตรง รุ่นที่ไม่มีรูปจะไม่แสดงกรอบรูป จับคู่รูปกับรุ่นด้วยรหัส เช่น `byd-atto3` ใช้กับ `byd-atto3-std` และ `byd-atto3-ext`

### เพิ่ม/แก้รุ่นรถ

แก้ `assets/js/cars.js`: `kwh` = แบตที่ใช้ได้, `use` = กินไฟเฉลี่ย kWh/100 กม., `dc` = ชาร์จ DC สูงสุด kW, `plugs` = หัว DC ของรถ ค่าที่ใส่ไว้เป็นค่าประมาณจากสเปกผู้ผลิตและผู้ใช้จริง (ตุลาคม 2569: 136 รุ่น จาก 40 ยี่ห้อ ยี่ห้อที่บอกแค่ความจุแบตรวม ใช้ราว 94% เป็นแบตที่ใช้ได้ แหล่งอ้างอิงที่ดีสำหรับรุ่นที่ขายในไทย: [Grab: รวมรถ EV](https://www.grab.com/th/blog/driver/ev-cars/))

**เพิ่ม/แก้/ซ่อนรุ่นรถจากหน้าหลังบ้าน** (ส่วน "รุ่นรถ" ใน `admin.html`) ไม่ต้องแก้โค้ด: เก็บในตาราง `cars` ของ Supabase แล้วหน้าเว็บโหลด `/api/cars.js` ต่อจาก `cars.js` (`lib/cars.mjs`) แถวที่ id ตรงกับรุ่นในโค้ด = แก้ตัวเลขรุ่นนั้น, id ใหม่ = เพิ่มรุ่น, ซ่อน = เอาออกจากรายชื่อ (เช่น เลิกขาย) กด "ลบการแก้ไข" เพื่อกลับไปใช้ค่าในโค้ด (ต้องรัน `db/schema.sql` อีกครั้งเพื่อสร้างตาราง `cars`)

ผู้ใช้ที่ไม่เจอรุ่นของตัวเองเลือก "อื่น ๆ → ไม่มีรุ่นของฉัน (ระบุเอง)" ใส่ยี่ห้อ รุ่น และสเปกได้ทันที คำขอจะขึ้นในหน้าหลังบ้าน (ข้อความจากผู้ใช้ หัวข้อ 🚗 ขอเพิ่มรุ่นรถ) ตรวจสเปกแล้วเพิ่มบรรทัดใน `cars.js` (id ใหม่ห้ามซ้ำ และระวังไม่ให้ขึ้นต้นเหมือน key ใน `data/car-images.json` ของรุ่นอื่น เพราะรูปจับคู่จากต้น id)

ผู้ใช้ใส่ **รูปรถของตัวเอง** ได้ (ปุ่ม "รูปรถของคุณ") รูปถูกย่อเหลือ 1280 px และเก็บในเบราว์เซอร์นั้นเท่านั้น ผูกกับยี่ห้อ/รุ่นที่เลือก

| บริการ | ใช้ทำ | เรียกผ่าน |
| --- | --- | --- |
| [Valhalla](https://valhalla1.openstreetmap.de) (FOSSGIS) | คำนวณเส้นทาง | `POST /api/route` |

## วิธีรัน

ต้องมี Node.js 18 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
npm start            # หรือ node server.mjs → http://localhost:8080 (เปลี่ยนพอร์ตด้วย PORT=3000)
npm test             # ทดสอบตัววางแผน (node:test)
OCM_KEY=xxxx npm start   # เปิดใช้ข้อมูล Open Charge Map (สมัคร key ฟรีที่ openchargemap.org)
```

## Deploy บน Render

1. New + → **Web Service** → เลือก repo `medtrackq/evroute`
2. Runtime: **Node** · Build Command: `npm install` · Start Command: `npm start` · Instance: **Free** · Region: Singapore
3. Environment → เพิ่ม `GITHUB_TOKEN` และ `GITHUB_REPO` (เพื่อเก็บสถานีที่ผู้ใช้เพิ่ม ดูหัวข้อด้านบน) และ (ไม่บังคับ) `OCM_KEY`, `GOOGLE_PLACES_KEY` + `GOOGLE_MAPS_KEY`, `SUPABASE_URL` + `SUPABASE_KEY`
4. กด Create แล้วรอจนขึ้น "Deploy live"

Render แบบฟรีจะหลับเมื่อไม่มีคนใช้ ครั้งแรกที่เปิดอาจรอ ~30 วินาที
